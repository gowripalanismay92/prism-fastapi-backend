# Prism BOB API — FastAPI backend for Databricks Apps

A separately deployable Python/FastAPI API that serves the mock Equitable-style Book of Business CSV. The API contract is stable and returns summary metrics, product/status mix and advisor records.

## Architecture

```text
Prism frontend (Databricks App)
  └─ server-side route resolves signed-in user's Entra employeeId
       └─ Databricks SDK WorkspaceClient() obtains app M2M bearer token
            └─ HTTPS GET /api/v1/advisors/{employeeId}/bob
                 └─ Databricks Apps OAuth ingress validates token
                      └─ FastAPI router → service → CSV repository
```

**Security boundary:** Do not trust browser-supplied advisor IDs. The frontend server must resolve the signed-in user's Entra employeeId and pass it to this API. Grant the frontend app's dedicated service principal `CAN USE` permission on this backend app. Databricks Apps validates the bearer token at ingress. The backend does not treat `X-Forwarded-User` as a service-principal ID: Databricks documents it as the IdP user identifier, so comparing it to the app SP ID is not a valid M2M caller check.

Each Databricks App has its own dedicated service principal. From another Databricks App, use `WorkspaceClient()` with the automatically injected app credentials; don't copy the backend or frontend app's secret into code. See the Databricks links in the deployment guide.

- `GET /health/live`
- `GET /health/ready`
- `GET /api/v1/advisors/{advisor_id}/bob`
- Interactive docs: `/docs` (disable or restrict in production if required by policy)

`GET /api/v1/advisors/GP00334146/bob`

## Deploy to Databricks Apps

1. In the workspace, create a new Databricks App named `prism-bob-api`.
2. Upload/sync the entire contents of this project folder (including `app/`, `data/`, `app.yaml`, and `requirements.txt`) to the app's source folder. Keep the relative paths unchanged.
3. Deploy the app. Its `app.yaml` runs `uvicorn app.main:app --host 0.0.0.0 --port 8000`.
4. Open the app's Authorization tab and note its app URL. Confirm the app exposes the `/api/` routes.
5. Open the existing Prism frontend app's Share/permissions UI. Grant the frontend app's dedicated service principal `CAN USE` on `prism-bob-api`. Each app has its own service principal; use the frontend app SP identity here.
6. Ensure the backend is not granted broader access than required. Databricks Apps does not support anonymous/public app access.
7. Test `/health/ready` in the browser. Then test the API using a bearer token generated by the frontend app (next section).
8. Review app logs for startup and CSV load errors.

## Frontend-to-backend M2M call (inside the existing frontend app)

Install/use `databricks-sdk` in the frontend requirements. In the frontend server route:

```python
import os
import requests
from databricks.sdk import WorkspaceClient

def call_bob_backend(backend_url: str, advisor_id: str) -> dict:
    # Uses the frontend app's own DATABRICKS_CLIENT_ID/SECRET injected by Databricks.
    workspace_client = WorkspaceClient()
    auth_headers = workspace_client.config.authenticate()

    response = requests.get(
        f"{backend_url.rstrip('/')}/api/v1/advisors/{advisor_id}/bob",
        headers=auth_headers,
        timeout=(5, 30),
    )
    response.raise_for_status()
    return response.json()
```

The frontend app must resolve the current signed-in user's Entra employeeId on the server before calling `call_bob_backend`. For this requested configuration, the employee ID and advisor ID are the same: `GP00334146`. Never take `advisor_id` from a query parameter or browser request body.

Set only the backend URL in the frontend app environment:
- `BOB_BACKEND_URL=https://<deployed-backend-app-host>`

The SDK's app authentication automatically uses the frontend app's injected app credentials. Do not manually copy `DATABRICKS_CLIENT_SECRET` into YAML, a source file, or a user-managed secret.

## Operational recommendations before production

- Replace the CSV repository with a governed Unity Catalog table/volume or approved data service. Keep the repository interface and response contract stable.
- Add pagination and filters before serving large advisor books.
- Add structured audit events for advisor ID, frontend caller identity (where available from trusted context), request ID, result count and outcome; never log tokens or sensitive customer fields.
- Set API rate limits and request timeouts at the platform/gateway layer if required.
- Keep PII out of routine logs. Use synthetic data in development.
- Define data retention, ownership, data quality checks and a formal advisor-to-employee identity source.
- Consider adding a backend-level signed claim/allowlist if additional caller restrictions beyond Databricks `CAN USE` permissions are mandated by your security team.
